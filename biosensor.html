I worked on a real-time biosensing platform that collects, logs and displays electrochemical and temperature data. The work spanned low-level firmware and a mobile app, creating one system for monitoring cardiovascular biomarkers.

Embedded Firmware & Hardware Communication

I worked on firmware integration for the STM32WB55RG microcontroller. Using STM32CubeIDE, I helped configure system clocks, GPIOs and peripherals to manage the system's data flows.

  • SPI integration: Adapted Analog Devices SDKs to communicate with the AD5940 potentiostat for precise electrochemical measurements.
  • I²C & DMA: Implemented I²C temperature sensing, using Direct Memory Access (DMA) for the non-blocking data transfers a real-time system needs.
  • Data logging: Integrated a FATFS file system for microSD logging, with a timestamp-based file-naming scheme that prevents data from being overwritten during long monitoring sessions.

Mobile Application Development

To make the data accessible, I contributed to a cross-platform Flutter mobile app.

  • UI: Designed front-end components in Dart to make navigation and data easier to read.
  • Real-time data: Built asynchronous handling for live data streams from the microcontroller over Bluetooth Low Energy (BLE).
  • User control: Built custom pages such as a sampling-interval setting, so users control how often the sensors report.

Reflection

This project taught me more about my goals than about biosensing itself. Coming into electrical engineering, I thought I wanted to work on biomedical applications, specifically robotic prosthetics. So when I found a research opportunity focused on detecting proteins in the blood, I was thrilled — it felt like the closest project yet to what had originally drawn me to engineering.

But when my role shifted early on from PCB design to microcontroller programming, I learned that passion for a product isn't the only thing that matters. The work that goes into building a device like this is diverse, and not every piece of it is for me. I didn't enjoy the firmware side nearly as much — navigating a codebase that had been passed between several undergraduates before me was tedious in a way that circuit design never was, and I found myself far more energized by the hardware problems than the software ones.

That distinction was the real takeaway. Having a biomedical application wasn't what made a project meaningful to me — circuit design was. My interest turned out to be less about the final product and more about the process of designing hardware to meet a complex problem's constraints. This project pushed me to stop assuming I knew what I'd enjoy and to actually go try things, which is exactly what led me to get involved across so many different corners of engineering since. I can't know what I like until I've tested it against the real thing.
